# Example Project Documents Structure

This directory shows the expected `project_documents/` structure that skills read from and write to.

## Structure

```
project_documents/
├── analysis/
│   ├── statement_of_the_problem.md
│   ├── concept_note_and_idea_validation.md
│   ├── feasibility_study.md
│   ├── proposal_and_technical_blueprint.md
│   ├── requirements_specification.md
│   └── risk_analysis_and_threat_modelling.md
├── design/
│   ├── design_principles_and_constraints.md
│   ├── presentation_layer_ui_ux_wireframes.md
│   ├── logic_algorithms_workflows_data_structures.md
│   ├── backend_apis_dal_database.md
│   ├── cross_cutting_architecture.md
│   ├── design_documentation_and_review.md
│   └── phase_gate_design_exit_review.md
├── development/
│   ├── coding_integration_debugging_standard.md
│   └── development_exit_review.md
├── validation/
│   └── validation_report.md
├── verification/
│   └── verification_report.md
├── testing/
│   ├── testing_and_quality_assurance.md
│   ├── alpha_testing_report.md
│   ├── performance_checks_report.md
│   └── compliance_to_standards.md
└── deployment/
    └── (deployment artefacts generated by deployment skills)
```

## Usage

1. Create this structure in your project root:
   ```bash
   mkdir -p project_documents/{analysis,design,development,validation,verification,testing,deployment}
   ```

2. Create an `idea.md` file in your project root (required by `/statement-of-the-problem`):
   ```markdown
   # Project Idea
   
   Brief description of the product concept, problem it solves, and target users.
   ```

3. Run skills in sequence:
   ```bash
   /statement-of-the-problem
   /concept-note-and-idea-validation
   /feasibility-study
   /proposal-and-technical-blueprint
   /requirements-specification
   /risk-analysis-and-threat-modelling
   ```

## Notes

- Skills overwrite their output files — commit changes to track evolution
- Each stage's outputs feed the next stage's inputs
- Exit review skills (`/phase-gate-design-exit-review`, `/development-exit-review`) validate completeness before stage transition
